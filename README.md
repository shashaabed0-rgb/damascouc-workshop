# مركز الدمشقي للصيانة — نسخة تجريبية متصلة بـ Supabase

## ملفات النشر
ارفع محتويات هذا المجلد إلى جذر مستودع `damascouc-workshop` فقط:
- `index.html`
- `config.js`
- `supabase.sql`
- `manifest.json`

## إعداد الاتصال
ملف `config.js` مضبوط على مشروع Supabase الذي زودني صاحبه برابطه ومفتاح Publishable.
مفتاح Publishable مخصص للواجهة العامة، لكن أمان البيانات يعتمد على RLS.

## تجهيز حسابات المدير
لا يمكن إنشاء مستخدمي Supabase Auth باستخدام مفتاح Publishable من ملف HTML.
أنشئ الحسابين يدوياً من Supabase Dashboard > Authentication > Users > Add user:
- `admin@abed.com`
- `abbar@abbar.com`

كلمة المرور `123456` التي اختارها صاحب المشروع قصيرة وضعيفة؛ استخدمها للتجربة المؤقتة فقط إذا قبلت إعدادات Supabase ذلك، ثم غيّرها فوراً إلى كلمة مرور قوية وفريدة. إذا رفض Supabase كلمة المرور، اختر كلمة مرور أطول. لا تشارك كلمات المرور في ملفات GitHub.

## حسابات الموظفين
أنشئ حسابات الموظفين من Authentication > Users، أو استخدم التسجيل من التطبيق إذا كان التسجيل العام مفعّلاً. التطبيق يفرض 8 أحرف على الأقل عند التسجيل من الواجهة.

## تحذير التجربة
هذا إصدار اختبار للمزامنة فقط. SQL الحالي يسمح لكل مستخدم مسجل بقراءة وكتابة سجل الأجهزة المشترك كاملاً. لا تستخدم بيانات زبائن أو ديون حقيقية قبل تنفيذ فصل البيانات المالية وسياسات RLS المناسبة.

## النشر
فعّل GitHub Pages على `main` و`/(root)` في المستودع `damascouc-workshop`.
في Supabase > Authentication > URL Configuration أضف رابط GitHub Pages إلى Site URL وRedirect URLs.
