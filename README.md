# مركز الدمشقي للصيانة — GitHub Pages + Supabase

## محتويات المشروع
- `index.html`: التطبيق الأصلي بواجهته ووظائفه مع تسجيل دخول ومزامنة سحابية.
- `config.js`: ضع فيه رابط مشروع Supabase ومفتاح anon/publishable.
- `supabase.sql`: إنشاء جدول مساحة العمل وسياسات RLS.

## 1) إعداد Supabase
1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor والصق محتوى `supabase.sql` ثم نفّذه.
3. من Project Settings > API انسخ Project URL ومفتاح `anon` أو `publishable`.
4. افتح `config.js` واستبدل `YOUR_SUPABASE_PROJECT_URL` و`YOUR_SUPABASE_ANON_KEY` بالقيم الحقيقية.
5. من Authentication > URL Configuration أضف رابط GitHub Pages ضمن Site URL وRedirect URLs بعد معرفة رابط المستودع المنشور.
6. من Authentication > Providers تأكد أن Email مفعّل. يمكن تعطيل التسجيل العام بعد إنشاء حسابات الموظفين المطلوبة.
7. من Database > Replication/ Publications تأكد أن جدول `public.shared_workspace` مضاف إلى `supabase_realtime` حتى تصل التحديثات المباشرة.

## 2) إنشاء حسابات الموظفين
- افتح التطبيق، أدخل بريد الموظف وكلمة مرور لا تقل عن 8 أحرف، ثم اختر «إنشاء حساب موظف».
- إذا كان تأكيد البريد مفعلاً، يجب تأكيد البريد أولاً ثم تسجيل الدخول.
- جميع الحسابات المصادق عليها تشترك في مساحة بيانات واحدة للمركز. لذلك أنشئ الحسابات للموظفين الموثوقين فقط.

## 3) النشر على GitHub Pages
1. أنشئ مستودع GitHub جديداً.
2. ارفع `index.html` و`config.js` و`supabase.sql` و`README.md` إلى جذر المستودع.
3. من Settings > Pages اختر Deploy from a branch ثم `main` و`/(root)` واحفظ.
4. انتظر ظهور رابط الموقع، ثم أضفه في Supabase Authentication > URL Configuration.
5. افتح الرابط عبر HTTPS وسجّل الدخول. تشغيل قارئ QR والكاميرا يتطلب HTTPS وإذن الكاميرا.

## ملاحظات مهمة
- لا تضع `service_role` أو أي مفتاح سري في `config.js`. مفتاح anon/publishable فقط هو المناسب للواجهة مع RLS.
- بيانات الأجهزة تُخزّن في جدول واحد مشترك (`shared_workspace`) بصيغة JSONB، وهذا مناسب كبداية لمركز صغير. عند تعديل الموظفين للبيانات في اللحظة نفسها قد يحدث تعارض «آخر حفظ يفوز»؛ قبل الاستخدام التشغيلي المكثف يُفضّل ترقية التخزين إلى جدول مستقل لكل جهاز مع صلاحيات وسجل تدقيق.
- إعدادات الواجهة المحلية مثل الشعار وبعض خيارات واتساب وأنواع الأجهزة تبقى محلية في هذا الإصدار؛ المزامنة السحابية الأساسية تشمل ملفات الأجهزة وبياناتها.
- إذا كانت لديك بيانات قديمة على جهازك، سجّل الدخول أول مرة من الجهاز الذي يحتوي على النسخة الأحدث. إذا كانت مساحة Supabase فارغة، سيُرفع محتوى هذا الجهاز تلقائياً. إذا كانت مساحة Supabase تحتوي بيانات، فستُحمّل البيانات السحابية فوق المحلية.
- لا يوجد ملف `logo.jpg` ضمن المرفقات التي وصلتني؛ أضفه إلى جذر المستودع إذا أردت ظهور الشعار الافتراضي كما في النسخة الأصلية.
